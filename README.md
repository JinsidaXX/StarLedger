# 星图账本：开源生活费规划与日常记账 App

> **项目名称：** 星图账本  
> **英文名称：** StarLedger  
> **项目类型：** 免费、开源、离线优先的个人记账与生活费规划 App  
> **目标平台：** Android，后续可考虑跨平台  
> **开源平台：** GitHub  
> **当前版本：** V0.1 MVP 规划  
> **许可证建议：** GPL-3.0-or-later  
> **核心口号：** 让每一笔生活费，都有自己的轨道。

---

# 一、项目概述

## 1.1 项目背景

现在很多记账软件存在以下问题：

- 操作步骤太复杂；
- 需要填写大量字段；
- 过度强调统计图表；
- 用户只能在消费发生后查看结果；
- 预算功能不够直观；
- 经常发送提醒和提问；
- 很多软件包含广告、会员或金融产品推荐；
- 记录一段时间后，用户很容易放弃。

星图账本希望做一款简单、安静、长期可用的开源记账软件。

它主要面向：

- 需要管理生活费的大学生；
- 刚开始独立管理收入的年轻人；
- 希望知道“钱还能花多久”的用户；
- 想逐渐培养消费规划习惯的人。

产品不追求让用户极度节省，而是帮助用户更清楚地知道：

- 生活费从哪里来；
- 每个月应该如何安排；
- 日常消费是否接近自己的计划；
- 哪些支出是必要的；
- 哪些钱可以放心使用；
- 一年下来，自己的消费习惯发生了什么变化。

# 二、产品定位

## 2.1 一句话定位

> 一款面向学生和年轻用户的免费开源 App，帮助用户完成日常记账、生活费分配、消费规划和月度复盘。

## 2.2 产品核心闭环

```text
收到生活费
    ↓
分配生活费
    ↓
日常记账
    ↓
查看各分类剩余金额
    ↓
重要消费提前规划
    ↓
月底查看本月情况
    ↓
生成一颗月度恒星
    ↓
十二个月组成一个年度星座
```

## 2.3 产品不做什么

本项目明确不做以下功能：

- 股票；
- 基金；
- 投资收益；
- 证券交易；
- 自动理财；
- 具体金融产品推荐；
- 贷款推荐；
- 用户之间的财富排行榜；
- 广告；
- 会员付费墙；
- 强制绑定账号；
- 强制接入 AI；
- 强制上传数据到服务器。

项目只关注：

> **生活费管理、日常消费记录和长期消费习惯。**

# 三、免费与开源原则

## 3.1 完全免费

App 本身完全免费：

- 无广告；
- 无会员；
- 无订阅；
- 无功能锁；
- 无付费主题；
- 无金融产品推广；
- 无数据售卖；
- 无强制云服务。

如果未来加入 AI 接口，用户自愿使用自己的第三方 API，第三方 API 产生的费用由第三方服务商收取，但 App 本身不向用户收费。

## 3.2 默认本地运行

MVP 默认采用离线优先设计：

- 数据保存在用户手机本地；
- 没有账号也可以使用；
- 没有网络也可以记账；
- 不上传用户账单；
- 不收集用户消费行为；
- 不依赖服务器才能使用核心功能。

## 3.3 开源许可证

建议使用：

```text
GPL-3.0-or-later
```

原因：

- 允许用户自由使用、修改和分发；
- 适合完全开源的软件项目；
- 鼓励修改后的版本继续开源；
- 可以防止其他人直接拿项目代码做成闭源商业软件。

如果希望代码被更多项目自由复用，也可以选择 MIT License，但 MIT 不要求衍生项目继续开源。

推荐仓库包含：

```text
LICENSE
README.md
CONTRIBUTING.md
CODE_OF_CONDUCT.md
SECURITY.md
CHANGELOG.md
```

# 四、目标用户

## 4.1 主要用户：大学生

典型场景：

> 用户每个月从家里收到 2,000 元生活费，希望知道这笔钱如何安排，避免月初花得太快，月末没有生活费。

可能的生活费来源：

- 家庭生活费；
- 奖金；
- 工资；
- 临时补贴；
- 红包；
- 退款；
- 其他收入。

产品中不一定使用“工资”这个词，而是使用更广泛的：

- 本期收入；
- 本月生活费；
- 本周期资金；
- 收入分配。

## 4.2 次要用户

- 刚毕业、开始管理工资的人；
- 月收入不稳定的自由职业者；
- 希望管理零花钱的用户；
- 想开始记账但不喜欢复杂工具的人。

# 五、产品设计原则

## 5.1 简单优先

日常记账必须足够简单。

一次普通支出只需要填写：

1. 金额；
2. 分类；
3. 账户。

商户、备注、标签、照片等全部设为可选。

## 5.2 安静优先

App 默认不频繁询问用户。

不应该出现：

- 每花一笔钱就询问“为什么消费”；
- 每天提醒用户复盘；
- 每天提醒用户打卡；
- 预算超出后连续弹窗；
- 反复要求用户填写解释；
- 因为没有登录而提醒用户；
- 因为没有配置 AI 而反复提示。

## 5.3 用户主动触发

大多数复杂功能都应该由用户主动进入：

- 用户主动创建大额消费计划；
- 用户主动打开月度复盘；
- 用户主动开启提醒；
- 用户主动配置 AI；
- 用户主动添加高价值物品；
- 用户主动修改分配模板。

## 5.4 不制造羞耻感

App 不使用“失败”“不自律”“错误消费”等表达。

推荐使用：

- 超出当前计划；
- 当前分类需要关注；
- 本期结余较少；
- 这笔支出可能影响某个计划；
- 预算和实际生活存在差异；
- 可以考虑下个周期重新安排。

## 5.5 允许中断

用户可以几个月不使用 App。

重新回来后，可以：

- 直接开始当前周期；
- 补充最近几笔账；
- 导入账单；
- 只填写分类总额；
- 核对当前账户余额；
- 将过去的月份标记为“未记录”。

中断不会让星星消失，也不会让星座变黑。

# 六、核心功能范围

# 6.1 日常记账

日常记账是本项目的基础功能，必须优先做好。

## 支持的交易类型

- 支出；
- 收入；
- 账户转账；
- 退款；
- 报销；
- 信用卡消费；
- 信用卡还款，后续支持。

## 普通支出字段

| 字段 | 是否必填 |
|---|---|
| 金额 | 是 |
| 分类 | 是 |
| 账户 | 是 |
| 日期 | 默认当前日期 |
| 商户 | 否 |
| 备注 | 否 |
| 标签 | 否 |
| 图片 | 否 |
| 关联计划 | 否 |

## 默认消费分类

面向大学生，建议默认分类控制在 8～10 个：

- 饮食；
- 交通；
- 学习；
- 宿舍与生活；
- 通讯；
- 社交；
- 娱乐；
- 购物；
- 医疗与应急；
- 其他。

用户可以：

- 修改分类名称；
- 新增分类；
- 删除未使用分类；
- 调整分类顺序；
- 设置分类颜色和图标。

## 快速记账交互

```text
点击“＋”
    ↓
输入金额
    ↓
选择分类
    ↓
确认账户
    ↓
保存
```

目标：

> 普通支出在 5 秒左右完成记录。

## 快速操作

- 最近使用分类；
- 最近使用账户；
- 常用账目模板；
- 连续记账；
- 记账后撤销；
- 长按账目快速编辑；
- 支持桌面小组件；
- 支持通知栏快速记账，默认关闭。

---

# 6.2 账户管理

账户代表钱实际存放的位置。

## 默认账户

- 现金；
- 银行卡；
- 微信；
- 支付宝；
- 校园卡；
- 信用卡；
- 其他。

## 账户字段

- 账户名称；
- 账户类型；
- 当前余额；
- 初始余额；
- 是否计入总余额；
- 是否为负债账户；
- 账户颜色；
- 是否隐藏余额。

## 账户和预算的区别

必须明确区分：

```text
账户：钱实际在哪里
预算：这笔钱准备花在哪里
```

例如：

- 2,000 元生活费进入银行卡；
- 其中 800 元分配给饮食；
- 其中 300 元分配给娱乐；
- 钱仍然在银行卡中；
- 只有真正发生消费后，银行卡余额和对应预算才会减少。

---

# 6.3 生活费分配

## 生活费分配方式

用户收到一笔生活费后，可以使用模板进行分配。

支持：

- 固定金额；
- 按总收入比例；
- 按剩余金额比例；
- 最低金额；
- 最高金额；
- 剩余金额自动进入缓冲；
- 是否结转；
- 优先级。

## 大学生默认模板

例如每月生活费为 2,000 元：

| 分配项目 | 建议金额 |
|---|---:|
| 饮食 | 900 元 |
| 交通 | 200 元 |
| 学习 | 150 元 |
| 宿舍与生活 | 250 元 |
| 社交娱乐 | 250 元 |
| 应急备用 | 150 元 |
| 大额消费储备 | 100 元 |

这些只是初始模板，不是统一标准。

用户可以自由修改。App 不应该告诉用户“你的比例不健康”，而应该展示：

- 这个分类过去三个月平均花费；
- 当前预算是否经常不够；
- 哪些分类长期有结余；
- 哪些目标正在被稳定投入。

## 生活费不足时

如果用户本期收入低于平时：

```text
本期可分配金额：1,600 元
原计划金额：2,000 元
少于计划：400 元
```

App 只展示调整预览：

- 固定支出保持不变；
- 饮食减少 100 元；
- 娱乐减少 150 元；
- 大额消费储备减少 150 元。

用户可以：

- 接受建议；
- 自己修改；
- 直接跳过；
- 暂不分配。

不自动修改用户的计划。

## 未分配金额

如果收入没有完全分配：

- 显示“未分配”；
- 不把它当成支出；
- 不强制用户处理；
- 可以随时分配；
- 月末可以选择结转或归入缓冲。

---

# 6.4 本期可用金额

大学生通常最关心：

> 我现在还可以花多少钱？

首页展示：

```text
本期可放心使用
? 680
```

计算方式：

```text
可放心使用金额 =
饮食剩余
+ 生活剩余
+ 娱乐剩余
+ 可用缓冲
- 尚未支付的必要支出
```

以下金额默认不计入可放心使用：

- 应急备用；
- 已经为大额消费准备的资金；
- 尚未到期的固定支出；
- 已分配给其他目标的资金。

## 可选的每日可用金额

可以提供一个可选卡片：

```text
剩余可弹性使用金额：?680
距离本期结束：17 天
参考每日金额：?40
```

这个数字只作为参考，不作为打分，也不持续提醒用户。

用户可以关闭。

# 6.5 大额消费计划

大额消费不是强制功能，用户主动使用。

## 进入方式

用户可以主动点击：

```text
规划一笔消费
```

或者从愿望清单中创建。

不建议每次用户记下一笔大额支出后都自动弹窗询问。

## 消费计划字段

- 商品名称；
- 预计价格；
- 购买理由，可不填；
- 最早决定日期；
- 目标购买日期，可不填；
- 资金来源；
- 是否有替代方案；
- 备注。

## 冷静期

默认冷静期为 7 天。

支持用户设置：

- 关闭冷静期；
- 7 天；
- 14 天；
- 30 天。

冷静期中，用户只看到：

```text
距离可以决定还有 4 天
```

不要求用户每天回答问题。

## 计划结果

用户可以选择：

- 购买；
- 延期；
- 放弃；
- 更换方案；
- 暂不决定。

购买计划结束后，MVP 只保留购买记录和关联账目。

暂时不做：

- 使用次数；
- 商品价值评分；
- 维修记录；
- 二手出售；
- 日均使用成本；
- 单次使用成本。

这些功能放到后续版本。

# 七、星图系统

# 7.1 基本设定

- 一年是一张星座；
- 一个财务月是一颗恒星；
- 不同分类是恒星发出的星芒；
- 月度结余形成星环；
- 预算偏差在对应星芒上体现；
- 数据未完整时显示星雾；
- 大额消费计划可以作为彗星出现。

## 7.2 星图不是排行榜

星星的亮度只与用户自己的计划和执行情况有关。

不比较：

- 用户之间的收入；
- 用户之间的结余；
- 谁花钱更少；
- 谁的储蓄比例更高。

## 7.3 月度恒星组成

一颗恒星由以下元素组成：

| 元素 | 含义 |
|---|---|
| 星核 | 本期整体财务状态 |
| 星芒 | 各分类的计划与支出 |
| 星环 | 月末已经确认用途的结余 |
| 星雾 | 记录不完整 |
| 彗星 | 进行中的大额消费计划 |
| 光点 | 完成分配、复盘等行为 |

## 7.4 星芒分类

月度恒星最多显示 6～8 个一级分支：

- 饮食；
- 交通；
- 学习；
- 生活；
- 社交娱乐；
- 应急备用；
- 大额计划；
- 其他。

点击星芒后再查看具体分类。

## 7.5 星辉规则

不要简单使用：

> 剩余越多，星星越亮。

建议综合以下内容：

- 是否完成收入分配；
- 账目是否基本完整；
- 各分类是否大致符合计划；
- 是否保留了必要资金；
- 是否完成月末复盘；
- 是否主动处理了结余。

星辉主要用于视觉呈现，不展示一个让用户产生压力的“财务分数”。

## 7.6 结余规则

分类结余不会无限增加亮度。

```text
结余 0%：基础亮度
结余 5%：增加少量光点
结余 10%：增加中等星辉
结余 20%：达到该分类的最大额外亮度
超过 20%：不继续增加亮度
```

原因是防止用户故意设置过高预算来让星星变亮。

超过预算的分类只影响对应星芒，不会立即让整颗恒星变红。

## 7.7 颜色规则

| 情况 | 颜色 |
|---|---|
| 计划内 | 蓝白色 |
| 轻微偏差 | 暖黄色 |
| 明显偏差 | 橙色 |
| 严重超出计划 | 红色 |
| 账目不完整 | 灰蓝色星雾 |
| 结余被重新安排 | 金色星环 |

整颗星星只有在以下情况才变红：

- 本期整体支出明显超过可用资金；
- 使用了应急备用；
- 产生了无法覆盖的负余额；
- 多个重要分类同时严重超支；
- 必要生活费无法覆盖。

## 7.8 年度星座

年度星座页面可以查看：

- 十二颗恒星；
- 每个月的支出结构；
- 生活费变化；
- 结余变化；
- 预算变化；
- 哪些月份记录完整；
- 哪些月份处于星雾状态；
- 哪些月份出现了大额消费计划。

用户可以为每一年命名：

- “第一次认真管理生活费的一年”；
- “开始存钱的一年”；
- “少买冲动商品的一年”；
- “顺利毕业的一年”。

# 八、低打扰交互设计

这是本项目的重要要求。

## 8.1 默认关闭通知

默认不发送：

- 每日记账提醒；
- 每日预算提醒；
- 每日复盘提醒；
- 每日星图提醒；
- AI 分析提醒。

用户可以在设置中主动开启：

- 生活费到账提醒；
- 消费计划冷静期结束提醒；
- 月末复盘提醒；
- 自定义账单提醒。

## 8.2 月末不强制提问

月末不弹出长问卷。

默认只展示：

```text
本期已结束
总收入：?2,000
总支出：?1,760
剩余：?240

查看本期星图
```

用户可以直接关闭。

如果用户主动进入复盘页面，再提供：

- 查看预算偏差；
- 处理结余；
- 修改下期计划；
- 生成恒星。

所有问题均可跳过。

## 8.3 不对每笔消费追问

普通记账只记录账目。

不会自动问：

- 为什么买；
- 是否后悔；
- 是否值得；
- 是否冲动；
- 是否影响目标。

大额消费计划也只有用户主动进入时，才出现相关字段。

## 8.4 不使用连续签到

不设计：


没有配置 API 的用户不会看到持续的配置提醒。

## 9.2 AI 不是核心依赖

即使完全不使用 AI，App 也必须能够完成：

- 日常记账；
- 生活费分配；
- 分类预算；
- 结余查看；
- 星图生成；

## 9.3 用户自带 API

用户主动开启 AI 后，可以配置：

- API 地址；
- 模型名称；
- API Key。

API Key：

- 只保存在本地；
- 使用 Android Keystore 保护；
- 不上传到项目服务器；
- 不写入日志；
- 不参与备份；
- 可以随时删除。

## 9.4 AI 默认只接收汇总数据

默认不上传：

- 商户名称；
- 交易备注；
- 账单照片；
- 账户名称；
- 银行卡信息；
- 逐笔交易。

只发送类似以下数据：

```json
{
  "period": "2026-03",
  "income": 2000,
  "expense": 1760,
  "planned": 1800,
  "categorySummary": [
    {
      "name": "饮食",
      "planned": 900,
      "actual": 940
    },
    {
      "name": "娱乐",
      "planned": 250,
      "actual": 180
    }
  ]
}
```

## 9.5 本地规则分析

即使用户不用 AI，也可以提供基础的本地分析：

- 饮食连续三个月超支；
- 某个分类预算长期过高；
- 结余连续增加；
- 本期比上期支出增加；
- 生活费剩余过少；
- 计划内消费比例提高；
- 未分配资金过多。

这些内容由本地程序计算，不依赖模型。

## 记账

- 可以快速记录收入、支出和转账；
- 账目修改后统计实时更新；
- 转账不会被重复计算；
- 支出分类清晰；
- 账户余额基本准确。

- 可以记录每期生活费；

- 可以按比例分配；
- 可以查看各分类剩余金额；

- 可以手动创建大额消费计划；
- 可以设置冷静期；
- 可以延期、放弃或购买；
- 不会频繁自动弹窗询问；

## 星图

- 一个月生成一颗恒星；
- 十二个月形成年度星座；

- 星图不会因为用户中断而消失。

- 不登录也能使用；
- 不接入服务器也能使用；
- 不配置 API 也能使用全部核心功能；
- 数据可以导出；
- 没有广告和付费功能。

# 十八、项目最终定位

星图账本不是一个金融投资软件，也不是一个要求用户每天打卡的习惯管理工具。

它是一款：

> **免费、开源、安静、简单、面向学生生活费管理的长期记账 App。**

它的核心不是让用户花得越少越好，而是让用户逐渐知道：

- 自己每个月有多少生活费；
- 这些生活费应该如何安排；
- 日常消费是否接近真实计划；
- 哪些支出值得保留；
- 哪些预算需要调整；
- 一年下来自己的生活变化是什么。

最终产品闭环可以简化成：

```text
收到生活费
→ 分配生活费
→ 记录日常支出
→ 查看本期剩余
→ 主动规划重要消费
→ 月末随时查看总结
→ 生成一颗恒星
→ 一年形成一个星座
```

最重要的设计原则是：

> **不打扰用户，不评价用户，不强迫用户，只把钱和生活清楚地呈现出来。**

这样才更可能成为一款用户愿意使用一年、两年甚至更久的真正实用软件。
